# US3: bilingual browser retry

Root executed four real Playwright trials against isolated frontend15173/API18000 with real background workers: Persian/English ×1280/390px. All4 passed in41.7s. The trials reopened a remembered FAILED attempt, used keyboard actions, required fresh upload, asserted outgoing intent=retry/retry_of and a new attempt UUID, interrupted a status request, refreshed the same status and observed DONE with exactly one business start. Screenshots: runtime/browser-{en,fa}-{1280,390}.png.

The strengthened browser spec keeps the status route installed instead of calling `page.unroute`, reads the multipart body immediately, and waits until the fresh import reaches `done` before the next case. That stops a dropped Chromium body and a preparation slot left busy for the following Persian preview.

A rerun on 2026-11-13 against the already-running isolated API at `127.0.0.1:18000` and the Vite server at `127.0.0.1:15173` passed all four cases in 57.1s: English/Persian at 1280×800 and 390×844. Each case used keyboard retry, a fresh file, `intent=retry` with `retry_of`, one new attempt, an interrupted status request, the same-job refresh, then `intent=new` with no predecessor, a second worker completion, and a missing-link retry rejected with HTTP 400. Persian preview was not blocked by the English case. Log: [runtime/independent-browser.log](runtime/independent-browser.log). Screenshots: `runtime/browser-{en,fa}-{1280,390}.png`. This run used the acceptance containers that were already up; it does not by itself prove the later scratch-clock image.
