# منبع دانش و فهم درخواست Velora

این ابزار اسناد `docs/`، قراردادهای قابلیت و کد را به یک بسته زمینه با ارجاع تبدیل می‌کند تا عامل فهم درخواست، زبان مهندس و کارفرما را به مفاهیم مشترک محصول وصل کند. متن اصلی درخواست حفظ می‌شود؛ تفسیر عامل و تصمیم کارفرما دو چیز متفاوت باقی می‌مانند.

نسخه اول با Python 3.10+ و SQLite دارای FTS5 اجرا می‌شود و وابستگی Python جدیدی ندارد. خود ابزار مدل را راه‌اندازی نمی‌کند. سرویس انتخاب‌شده، مدل محلی Qwen3-Embedding-0.6B Q8_0 در LM Studio است؛ جست‌وجوی برداری پس از ساخت موفق index با `--semantic` فعال می‌شود. این ابزار مرحله retrieval و ساخت prompt را انجام می‌دهد؛ تولید تفسیر توسط عامل مصرف‌کننده و مطابق `agent-instructions.md` انجام می‌شود. ابزار، چت مستقل یا orchestrator اجرای کد نیست.

## شروع از ریشه مخزن

```bash
python3 scripts/knowledge/cli.py index
python3 scripts/knowledge/cli.py status
python3 scripts/knowledge/cli.py context "گزارش رو بستم ولی فرداش عدد کارگرا عوض شد" --format markdown
python3 scripts/knowledge/cli.py query "Trace rebuild_daily_report_summary aggregation"
python3 scripts/knowledge/cli.py eval --lexical
python3 -m unittest discover -s scripts/knowledge -p 'test_*.py' -v
```

معادل‌های pnpm: `knowledge:index`، `knowledge:status`، `knowledge:context`، `knowledge:query`، `knowledge:eval` و `knowledge:test`. متن درخواست را به فرمان context یا query اضافه کنید.

## مسیر فهم درخواست

1. نرمال‌سازی حروف عربی/فارسی، ارقام، فاصله و شناسه‌های فنی؛ متن اصلی تغییر نمی‌کند.
2. بازیابی جداگانه عبارت اصلی و گسترش واژه‌نامه با BM25؛ پیوند مفهوم به فایل مالک نیز نامزد منبع می‌آورد.
3. در حالت hybrid، افزودن شباهت برداری و ادغام رتبه‌ها با reciprocal rank fusion؛ رتبه‌ها احتمال درستی نیستند.
4. ساخت بسته شامل نامزدهای مفهوم، شاهد، نوع منبع، هش، محل دقیق، ابهام و freshness.
5. عامل فهم درخواست بسته را می‌خواند، منابع اصلی را بررسی می‌کند و تفسیر، معیارهای پذیرش پیشنهادی و سؤال‌ها را برمی‌گرداند. نبودن سؤال در قواعد واژه‌نامه به معنی کامل‌بودن درخواست نیست.

نمونه «گزارش رو بستم» سؤال درباره نوع گزارش و معنای بستن تولید می‌کند؛ عبارت «بستم» خودکار به وضعیت `approved` تبدیل نمی‌شود. نگاشت‌های محاوره‌ای `concepts.json` پیشنهادی‌اند و باید با نمونه‌های واقعی کارفرما بررسی شوند.

## منابع و اعتبار آن‌ها

- `docs/`: مستندات پروژه و کارفرما، با وضعیت تأیید نامعلوم مگر شواهد جدا وجود داشته باشد. هیچ متن صرفاً به دلیل قرارگرفتن در این پوشه، گفتگوی قطعی یا تصمیم مصوب تلقی نمی‌شود.
- `docs/decision-tree/`: رفتار مستندشده با نیاز به تأیید زمان اجرا؛ ناهماهنگی‌های فعلی validator رفع‌شده فرض نمی‌شوند.
- `specs/` و `reports_documentation/`: قرارداد و طراحی قابلیت؛ وضعیت پیاده‌سازی از وجود سند نتیجه نمی‌شود.
- `.specify/memory/constitution.md`: قواعد پروژه.
- `apps/api/core/` و `apps/web/src/`: منبع پیاده‌سازی و تعریف تست؛ به‌تنهایی اثبات اجرای موفق نیستند. migration و فایل‌های تولیدشده وارد نمی‌شوند.
- `knowledge/articles/`: راهنمای تفسیر پیشنهادی؛ `concepts.json`: پیوند زبان دامنه به منابع.
- `knowledge/sources/`: گفتگوها و اسناد واردشده با provenance و وضعیت unreviewed؛ این پوشه برای جلوگیری از commit ناخواستهٔ گفتگوها در gitignore است.

متن، کد، Markdown و DOCX پشتیبانی می‌شوند. در DOCX متن پاراگراف‌ها و سلول‌ها استخراج و با `P` ارجاع داده می‌شود؛ این ارجاع شماره صفحه نیست. تصاویر، شکل‌های جاسازی‌شده، سربرگ/پاورقی، چیدمان و متن حذف‌شدهٔ tracked changes تضمین پوشش ندارند. فایل‌های MPP و XML برنامه زمان‌بندی فعلاً وارد نمی‌شوند و به parser دامنه‌ای نیاز دارند. فایل‌های حساس با نام شناخته‌شده، محیط، symlink، فایل بیش از ۲ مگابایت و خروجی‌های تولیدشده کنار گذاشته می‌شوند. `status` فهرست skipهای داخل الگوهای پشتیبانی‌شده را نشان می‌دهد؛ فایل‌های با پسوند خارج از الگو اصلاً جزو corpus نیستند.

بسته شاهدها را حذف یا به‌صورت خودکار با هم سازگار نمی‌کند؛ تشخیص تعارض محتوایی با عامل فهم درخواست است. هدف پوشش متوازن مدارک نیاز و کد است، ولی کیفیت رتبه‌بندی باید با ارزیابی واقعی سنجیده شود.

## واردکردن گفتگوی جدید

متن اصلی را در `.txt`، `.md` یا `.docx` نگه دارید؛ سپس:

```bash
python3 scripts/knowledge/cli.py import /absolute/path/meeting.txt --title "گفتگوی گزارش روزانه" --origin "meeting-reference" --date 2026-11-03
python3 scripts/knowledge/cli.py index
```

در صورت معلوم‌بودن گوینده، `--speaker` را اضافه کنید. تاریخ، گوینده و منشأ نامعلوم را اختراع نکنید. ورودی byte-for-byte حفظ می‌شود؛ metadata در sidecar قرار می‌گیرد. ورود تکراری فایل، اطلاعات قبلی را بازنویسی نمی‌کند. تأیید نیازمندی باید در سند تصمیم یا spec ثبت شود؛ عامل نباید پاسخ تولیدی خودش را خودکار به سند تأییدشده تبدیل کند.

## اتصال embedding قابل تنظیم

سرویس باید قرارداد `POST` سازگار با `/v1/embeddings` داشته باشد: ورودی `model` و لیست `input`، خروجی `data` شامل `index` و `embedding` عددی. سرویس دیگر نیاز به adapter دارد.

نام متغیرها در `config.json` تنظیم می‌شود:

پروفایل پیش‌فرض فعلی: endpoint محلی `http://127.0.0.1:1234/v1/embeddings` و شناسه `text-embedding-qwen3-embedding-0.6b`. متغیرهای زیر در صورت وجود این مقدارها را override می‌کنند. قبل از استفاده، مدل باید در LM Studio بارگذاری شده و Local Server فعال باشد. طول زمینه انتخاب‌شده ۴۰۹۶، خروجی ۱۰۲۴بعدی و batch اولیه ۴ است. `query_prefix` دستور بازیابی انگلیسی مخصوص پرسش دارد و `passage_prefix` خالی است.

- `KNOWLEDGE_EMBEDDING_URL`: نشانی کامل endpoint؛ HTTPS برای سرویس بیرونی.
- `KNOWLEDGE_EMBEDDING_MODEL`: شناسه مدل سرویس انتخاب‌شده.
- `KNOWLEDGE_EMBEDDING_API_KEY`: کلید در محیط فرایند؛ آن را در چت یا فایل‌های نسخه‌بندی‌شده قرار ندهید.

متغیرهای عمومی OpenAI یا فایل `.env` پروژه خودکار استفاده نمی‌شوند. پس از انتخاب سرویس، متغیرها را با مدیریت اسرار یا محیط ترمینال تنظیم کنید و عمداً اجرا کنید:

```bash
python3 scripts/knowledge/cli.py index --semantic
python3 scripts/knowledge/cli.py context "چرا تعداد نیروی کارگاه بعد از تأیید تغییر می‌کند؟"
```

`index --semantic` متن corpus و query حالت hybrid متن پرسش را به سرویس انتخاب‌شده می‌فرستند. `--lexical` روی query/context/eval حتی با index برداری هیچ درخواست شبکه‌ای نمی‌فرستد. `index` بدون `--semantic` یک index صرفاً محلی می‌سازد و جایگزین نسخه hybrid قبلی می‌شود؛ mode همیشه در خروجی مشخص است.

مدل باید فارسی و انگلیسی را با هم پوشش دهد. اندازه chunk، محدودیت توکن و query/passage prefix را مطابق مدل تنظیم و قبل از index کامل، روی نمونه واقعی ارزیابی کنید. خطای endpoint، تغییر مدل یا ابعاد بردار به موفقیت ظاهری یا fallback بی‌صدا تبدیل نمی‌شود. هر batch موفق در `.knowledge/index.embeddings-cache.sqlite3` ذخیره می‌شود؛ اجرای دوباره با همان مدل، prefix و متن، بخش‌های انجام‌شده را تکرار نمی‌کند. تغییر اندازه batch این cache را بی‌اعتبار نمی‌کند. index جدید به‌صورت atomic جایگزین می‌شود و شکست، index قبلی را حفظ می‌کند. تغییر منابع حین اجرا مانع انتشار snapshot مخلوط می‌شود، ولی checkpointها برای اجرای بعد باقی می‌مانند.

## پیگیری اجرای embedding

`python3 scripts/knowledge/cli.py status` هم وضعیت index منتشرشده و هم آخرین اجرای embedding را نشان می‌دهد؛ حین ساخت اول، index قبلی هنوز lexical است. پیشرفت هر batch در `.knowledge/index.progress.json` ثبت می‌شود. اجرای پس‌زمینه این جلسه PID را در `.knowledge/embedding.pid`، خروجی را در `.knowledge/embedding-result.json` و گزارش پیشرفت/خطا را در `.knowledge/embedding.log` نگه می‌دارد. در صورت شکست، ابتدا علت را بررسی و سپس همان فرمان `index --semantic` را دوباره اجرا کنید. هنگام اجرای فعال، اجرای دوم را شروع نکنید.

## تازگی و ارزیابی

freshness بر اساس هش فایل‌ها، metadata، تنظیمات و واژه‌نامه است و تغییرهای commitنشده، افزودن و حذف فایل را تشخیص می‌دهد. query با index قدیمی خطا می‌دهد؛ `--allow-stale` فقط برای بررسی تاریخی است و بسته حاصل برای برنامه‌ریزی آماده نیست. پس از تغییر منابع، index را بازسازی کنید. build هم تغییر هم‌زمان منابع را بررسی می‌کند؛ برای انتشار شواهد نهایی، از checkout ثابت استفاده کنید.

`evaluation.json` شامل نمونه‌های دست‌نویس فارسی، محاوره‌ای، فنی، مبهم و نامرتبط است. عبور آن‌ها smoke test است، نه اندازه‌گیری دقت واقعی زبان کارفرما. مرحله بعد: نمونه‌های واقعی و جدا از نمونه‌های طراحی واژه‌نامه را با پاسخ مرجع انسانی اضافه کنید؛ مفهوم درست، شاهد مرتبط، سؤال لازم، خطای تفسیر و ادعاهای بدون شاهد را بسنجید.

[چارچوب ارزیابی بازیابی و فهم درخواست](evaluation/README.md) اکنون شامل مجموعه جداگانه development/holdout، معیارهای رتبه منبع و رد شواهد ناکافی، و بررسی قرارداد خروجی عامل با فرمان `eval-understanding` است. `retrieval-policy.json` آستانه‌های اولیه مخصوص مدل فعلی را نگه می‌دارد؛ اعتبار این آستانه‌ها روی نمونه‌های واقعی هنوز سنجیده نشده است.

تست‌های connector از سرویس HTTP محلی با بردار مصنوعی استفاده می‌کنند؛ این تست‌ها قرارداد اتصال، cache، ادامه اجرای قطع‌شده و رفتار خطا را می‌سنجند و کیفیت مدل embedding واقعی را ثابت نمی‌کنند. آزمون زنده اولیه Qwen با متن مرتبط فارسی/انگلیسی و متن نامرتبط در `.knowledge/lmstudio-smoke.json` ثبت شده است؛ این آزمون کوچک جای ارزیابی روی گفتگوهای واقعی را نمی‌گیرد. endpoint فعلی محلی است. ابزار برای محیط داخلی توسعه است؛ پیش از ارائه مستقیم به کاربران محصول باید کنترل دسترسی به اسناد به آن افزوده شود.

مرجع الگوریتم BM25 و FTS5: [مستندات رسمی SQLite](https://www.sqlite.org/fts5.html). راهنمای مصرف توسط عامل: [agent-instructions.md](agent-instructions.md).
